# Edge Type and Edge Instance Index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `EdgeType_relationship_name` strictly type-level while preserving per-edge semantic search in a new `EdgeInstance_text` collection and automatically rebuilding existing derived indexes from graph state.

**Architecture:** A shared edge-index builder produces `EdgeType` points keyed by relationship name and `EdgeInstance` points keyed by the existing `edge_object_id`. Standard, PostgreSQL hybrid, Neptune hybrid, retrieval, deletion, and migration paths consume those shared identities. The graph remains the source of truth for graph-wide counts, stale-point cleanup, and retryable migration.

**Tech Stack:** Python 3.10–3.13, Pydantic `DataPoint` models, asyncio, PostgreSQL/pgvector, Ladybug, Neo4j, Neptune Analytics, Turso, LanceDB, pytest/pytest-asyncio, Ruff.

## Global Constraints

- Work on `fix/edge-instance-text-index`, based on upstream `dev` commit `4acbe9a71ac7268cba426a20400a0c509207f72f`.
- Follow strict TDD: add one regression test, observe the expected failure, implement the smallest passing change, then refactor while green.
- Keep Ruff line length at 100 characters.
- `EdgeType_relationship_name` IDs must be `EdgeType.id_for(relationship_name)` and must never use `edge_text`.
- `EdgeInstance_text` IDs must reuse the exact existing `edge_object_id` generated by `generate_edge_object_id`; never copy its normalization logic.
- Edge identity is structural; edge text is mutable content.
- `EdgeInstance.text` uses nonblank `edge_text`, otherwise readable `relationship_name`; neither value contributes to its ID.
- `EdgeType.number_of_edges` equals the number of currently existing directed graph edges with that relationship name.
- Edge-instance deletion is driven by actual graph-edge deletion, not individual provenance removal.
- `Triplet_text`, triplet IDs, and optional triplet configuration remain unchanged.
- The migration rebuilds both collections from graph state, removes stale points, is retry-safe, and stamps only after both replacements succeed.
- Commits use imperative conventional subjects and DCO sign-off (`git commit -s`).

### Existing units modified

- Graph interface/adapters expose graph-wide relationship counts.
- Vector interface/adapters preserve new payload fields, replace vectors on upsert, and replace one collection without pruning unrelated collections.
- Standard and hybrid edge writers consume shared point construction.
- Hybrid and brute-force retrieval maintain separate type and instance ranking lanes.
- Direct, legacy, and provenance deletion use structural instance IDs and type IDs independently.
- Migration registry appends one immutable revision.

```python
async def get_edge_type_counts(self, relationship_names: List[str]) -> Dict[str, int]:
    requested = dict.fromkeys(relationship_names, 0)
    if not requested:
        return {}
    _, edges = await self.get_graph_data()
    for edge in edges:
        relationship_name = edge[2]
        if relationship_name in requested:
            requested[relationship_name] += 1
    return requested
```

- [ ] **Step 4: Add optimized adapter queries**

```sql
SELECT relationship_name, COUNT(*)
FROM graph_edge
WHERE relationship_name = ANY(:relationship_names)
GROUP BY relationship_name
```

Implement one-collection replacement in all four stores. PostgreSQL writes bounded batches into a

vector nodes whose collection marker matches before consuming batches. The non-PostgreSQL paths
remain retryable and collection-scoped. The PostgreSQL hybrid adapter delegates to its vector
adapter.
