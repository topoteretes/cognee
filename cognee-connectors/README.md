# cognee-connectors

Data-source connectors for [cognee](https://github.com/topoteretes/cognee), the open-source
AI memory platform. One package per source (Notion, Linear, GitHub, Slack, Google Drive, Gmail,
Google Calendar, Apollo, Asana, Obsidian, OneNote) turns that source's records into documents in
cognee memory — incrementally, with forget-on-delete — and carries the source's OAuth contract
so a cognee server or Cognee Cloud can connect it. Every connector is its own PyPI package built
on the shared contract `cognee-connectors-core`; cognee itself is a development dependency of
this workspace and never a runtime dependency of a connector
(see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)).

## Install

Install a connector from PyPI; you do **not** need to clone this repository to use one.

```bash
pip install cognee-connector-notion            # the connector and its DLT source
pip install "cognee-connector-notion[cognee]"  # plus the adapter for a cognee server (installs cognee)
```

Every package supports Python 3.10 through 3.14 and pins the shared contract
`cognee-connectors-core>=0.1,<1`.

## Using a connector

A connector exposes a DLT source factory (`<provider>_source`). Hand its result to
`cognee.remember()` and the records become documents in the dataset, synced incrementally:

```python
import cognee
from cognee_connector_notion import notion_source

await cognee.remember(
    notion_source(
        root_page_ids=["<page id from the page URL>"],
        resource_name="notion_<connection id>",
    ),
    dataset_name="my_notion_space",
    primary_key="id",
    write_disposition="merge",
    max_rows_per_table=0,
)

print(await cognee.recall("What did we decide about the launch?"))
```

The credentials a source needs are passed to the factory or read from the environment
variables the connector's README documents (names unchanged from cognee's `.env.template`;
see [`.env.template`](.env.template)).

## Running on a cognee server

A cognee server (1.6.x) hosts the OAuth flow, stores the credentials and runs the syncs. Install
the package with its `cognee` extra and register the provider before the app starts:

```python
from cognee_connector_notion.cognee_host import register

register()  # the connector appears in GET /api/v1/integrations/status
```

`cognee_connectors_core.registry.load_host_registrations()` does the same for every installed
connector at once. The OAuth flow then runs on the generic `/api/v1/integrations/notion/...`
routes; providers with routes of their own (Slack) expose `routers()` for the host to mount.
Configure the provider's OAuth app with the environment variables in
[`.env.template`](.env.template).

## Repository layout

```text
core/                     cognee-connectors-core: the contract (descriptor, OAuth2, webhook
                          verification, DLT conventions, registry, test helpers)
connectors/<provider>/    cognee-connector-<provider>: source.py, connector.py, settings.py,
                          cognee_host/, tests/, examples/, README.md
templates/connector/      what scripts/new_connector.py scaffolds a package from
scripts/                  packages.py, check_pins.py, check_cognee_free.py, check_entry_points.py,
                          clean_install.sh, validate_inventory.py, render_inventory.py, new_connector.py
docs/                     ARCHITECTURE.md, PORTING.md, RELEASE.md
inventory.yml             the connector catalog the table above is rendered from
```

This folder lives in the [cognee](https://github.com/topoteretes/cognee) repository, next to
`cognee-mcp/`, with its own uv workspace and lockfile. Its CI is in the repository's
`.github/workflows/`: `test_connectors.yml` (lint, inventory and pin checks, every package's
tests against the cognee in the checkout, and a cognee-free clean install) and
`release_connectors.yml` (per-package PyPI releases, see [docs/RELEASE.md](docs/RELEASE.md)).

## Development

`cognee-connectors/` is one uv workspace: `core/` and every `connectors/*` are members, cognee
comes in through the `dev` dependency group (from PyPI; CI swaps in the cognee of the checkout).
Run the commands below from `cognee-connectors/`.

```bash
uv sync --all-packages --group dev        # every package plus cognee, pytest, ruff, pre-commit
uv run pytest core/tests -q               # core; run one package per pytest call,
                                          # as CI does (test files share basenames)
uv run pytest connectors/notion/tests -q  # one package
uv run ruff check . && uv run ruff format --check .
uv run python scripts/validate_inventory.py
uv run python scripts/render_inventory.py --check
uv run python scripts/check_pins.py
```

The tests never call an LLM, but cognee needs to look configured and must not pick up a
`.env`:

```bash
export COGNEE_ENV_FILE=<an empty file>   # keep cognee from loading any .env
export TELEMETRY_DISABLED=1 LITELLM_MODE=PRODUCTION LLM_API_KEY=sk-test-dummy
```

Without a synced workspace, a Python that has cognee installed runs a package's tests straight
from the checkout: `PYTHONPATH=core:connectors/google:connectors/<p> python -m pytest
connectors/<p>/tests -q` (see [docs/PORTING.md](docs/PORTING.md)).

To add a connector: `python scripts/new_connector.py <slug> --display-name "..."` scaffolds
`connectors/<slug>/` from `templates/connector/` and lists it in `inventory.yml`; then follow
[docs/PORTING.md](docs/PORTING.md).
