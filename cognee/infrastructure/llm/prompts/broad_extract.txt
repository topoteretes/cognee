You extract items from a section of a larger corpus so they can be counted exactly by code. List EVERY matching item in this section, one entry per occurrence. Never count, estimate or summarize. Skip anything that does not satisfy the item definition and condition. For each entry give:
- key: the value of the identity attribute described below, in that exact format (the identifier alone, e.g. "20142", never "PR #20142 for issue #10142"), or null only if there is no identity attribute or this section truly does not show it;
- group: the value of the grouping attribute described below, written as it appears (resolve pronouns like "they" to the name they refer to), or null if none;
- groups: every value of the grouping attribute when one item has several (all four authors of a paper; both members of a connection), written as they appear; code makes one entry per value. Empty when the item has one value (put it in group);
- unit: the number N of the [unit N] block the item appears in;
- amount: when an amount to report is described below, the item's value of it as a plain number (e.g. 40 for "40 cameras", 1250.5 for "$1,250.50"), or null if the text does not state it; null when no amount is described;
- evidence: a short verbatim quote (at most 20 words) containing the words that make it match the item and condition — for an item that is a fact, the fact itself.
A "[document start — context only]" block repeats the first line of the document the following units come from (for example a table's column header). Use it to interpret those units; never list items from it.
- undone: only as the "Undone entries" line below allows. When it does, an entry recording that an item was later ended (a connection removed, an order cancelled after it was placed, a purchase returned) has undone = true, with the ended item's key and group exactly as the original entry would have them; code drops the original. Otherwise false.
An item that requires an event (imported, delivered, paid, opened, shipped) does not match a record whose text says that very event did not happen (the shipment was cancelled before loading, the payment was refunded, the request was rejected). Only the counted event matters: a run that failed still used its reagent; one aborted before any reagent was added did not.
Two items in different units are different items even when their quotes are identical (table rows often repeat the same values). Return an empty list if the section contains none.
Separately, in aliases, list every set of names that this section itself states refer to the same person or thing (e.g. "Akshats-git (usually called Akshats)", "Robert, known as Bob", "the CEO, Jane Doe"), whether or not they appear in an item. Only what the text states, never a guess.
